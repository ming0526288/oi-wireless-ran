# TEST-688 100 MHz 门限 0 后置开关核验

在 `cmake_targets` 执行 `CCACHE_DISABLE=1 ./build_oai -w DPDKRF --gNB --ninja -d ran_build_dpdkrf`，退出 0。使用相同的一份 gNB 二进制跑先后两组，SHA-256 均为 `21bab51194d8464436778b8afb8ca949fa61eab8652eaf007b616e06019dae65`。UE 程序沿用上一次构建，编译前后 SHA-256 一致。连续剩余 PRB 搜索用原函数作参照，通过 106,494 个掩码及申请长度组合。

复用原核心网和三个已登记订阅的 UE 命名空间。gNB、UE 各在构建目录的独立终端直接启动。条件固定为 100 MHz、120 kHz、门限 0、DDDSU 和 MCS 上限 9。gNB 从默认模式切为后置时只在 `sudo -n` 后加 `OAI_RESEARCH_PROBE_POLICY=residual`。两组日志分别显示 `[UL probe] policy=legacy` 和 `[UL probe] policy=residual`。每组按上一台获得 TUN 地址后再开启下一台的顺序接入。

默认模式先做双 UE 连通回归，两个 UE 同期各发 20 个 56 B ping，均为 20／20，均值 1.653／1.657 ms，保留全部 20 包。第三个 UE 完成过随机接入竞争解决，多次重试后仍未取得业务地址，gNB 在 `nr_generate_Msg4` 的 `tb_size >= pdu_length` 检查退出。三 UE 业务和抓包均未开始。该表现与 TEST-687 的原顺序一致。

后置模式三台均获 IPv4 和业务路由。各用下列形式独立发 200 包，三台同期发包。每台前 20 个序号预热，后 180 个用于统计。

```bash
sudo -n ip netns exec s2m56u0 ping -D -n -I oaitun_ue1 -c 200 -s 56 -i 0.02 -W 2 172.11.200.25
```

| 后置模式 | 发出／收到 | 平均 RTT（ms） | P99（ms） |
|---|---:|---:|---:|
| UE 1 | 200／200 | 2.378 | 3.455 |
| UE 2 | 200／200 | 2.468 | 3.714 |
| UE 3 | 200／200 | 7.664 | 13.800 |

复用 `step2-multiue56-v1/ping_capture.py`，配对 600 次完整事务，逐 UE 上下行各 200 个 QFI 9，捕获通过。第三台在成功接入后的平均 RTT 仍高于前两台。默认组三 UE 无 RTT，本对照用于验证接入与开关，不量化三 UE 时延降幅。

后置组各 UE 和基站正常退出，宿主查无本次 RAN、抓包、监听端口和 UE TUN 残留。原三核心容器启动时间一致。完整构建日志、ping 输出、TUN／N3 抓包和终端节选保存在本机 `analysis-source-audit/gate0-100MHz-probe-switch-20261125/`。真实射频未执行。
